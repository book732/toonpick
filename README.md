# 오늘의 덕질

취향에 맞는 다음 웹툰을 발견하는 추천 사이트입니다. 기존 TripSpark 프로젝트의 가벼운 HTML/CSS/JavaScript 구조를 유지하면서 웹툰 탐색 서비스로 변경했습니다.

- 공식 목록 자동 수집과 실시간 작품검색을 결합한 AI 추천, 작품별 추천 이유
- 제목·작가·태그 검색, 추천순·관심등록순·가나다순 정렬
- 국내 웹툰·만화 19개 서비스 모아보기, 플랫폼별 탐색·추천 대상 선택, 공식 감상 페이지 연결
- 브라우저 보관함 저장·삭제, 다크 모드
- 데스크톱·태블릿·모바일 반응형 화면, 키보드로 사용할 수 있는 모달

## 실행

애니메이션 추천은 `/anime`에서 제공합니다. 웹툰과 같은 화면·보관함·추천 개수·로딩 코드를 공유하며, 작품 형식·방영 상태 필터와 시즌 정보는 애니메이션 전용입니다. [애니메이션 구현·출처 문서](docs/ANIME.md)를 참고하세요.

보드게임 추천은 `/boardgames`에서 제공합니다. 스플렌더·더 게임을 포함한 18개 기본 게임을 수록하고 인원·시간·난이도 상한과 AI 취향 추천을 지원합니다. [보드게임 구현·출처 문서](docs/BOARDGAMES.md)에 범위와 기준을 기록했습니다.

저장소에서 `python dev_server.py`를 실행하고 터미널에 표시되는 주소로 접속합니다. 기본 포트는 8080이며 사용 중이면 다른 포트를 자동 선택합니다.

일반 탐색은 API 키 없이 동작합니다. AI 추천은 기존 Windows 전역 환경변수 `AI_API_KEY`, `AI_API_BASE_URL`, `AI_MODEL`을 서버에서 읽습니다. 현재 연결 방식은 `3-2/main.py`와 같은 OpenAI 호환 Chat Completions입니다. 별도 Python 패키지는 필요하지 않습니다.

`AI_API_BASE_URL`은 코디세이 게이트웨이의 `https://copa.codyssey.kr/v1`, `AI_MODEL`은 기존 설정인 `gpt-5.5`를 사용합니다. 실제 키를 소스 코드·HTML·브라우저 저장 공간에 넣지 않습니다. 환경변수를 변경하면 서버를 다시 실행합니다. 프로젝트별 설정이 필요하면 `.env.example`을 참고해 Git에서 제외되는 `.env`에 설정할 수 있습니다.

HTML 파일을 직접 열거나 일반 정적 서버만 실행하면 AI 추천을 호출할 수 없습니다. 반드시 `python dev_server.py`를 사용합니다.

## 구조와 추천 방식

| 파일 | 역할 |
| --- | --- |
| `index.html` | 메인 화면, 검색·필터·취향 선택 및 상세 모달 |
| `css/style.css`, `css/dark-mode.css` | 반응형 화면과 테마 |
| `js/api.js` | 카탈로그 1회 로드, 검색·필터·정렬, 서버 AI 추천 요청과 응답 검증 |
| `services/recommendations.py` | 기존 전역변수로 AI 호출, 후보 제한, 작품 ID와 추천 이유 검증 |
| `api/generate.py` | 기존 POST `/api/generate`에서 `type=webtoon` 요청 처리 |
| `js/app.js` | 화면 상태, 이벤트 위임, 모달, 저장 버튼 |
| `js/storage.js` | 기존 StorageManager 메서드로 관심 작품과 테마 저장 |
| `data/webtoons.json` | 공식 목록에서 자동 수집한 작품의 배포용 스냅샷 |
| `services/catalog.py` | 공식 목록 수집, 24시간 갱신, 실시간 검색과 후보 선정 |
| `services/platforms.py` | 국내 플랫폼별 공개 검색·HTML·메타데이터 어댑터와 출처 검증 |
| `data/platforms.json` | 19개 서비스의 공식 주소·작품 경로·이미지 호스트 |
| `.cache/` | Git에서 제외되는 실행 중 카탈로그·개별 작품 메타데이터 캐시 |
| `assets/covers/` | 로컬 제공 표지 이미지 |
| `public/` | Vercel 정적 배포용 동일 파일 |
| `scripts/update_catalog.py` | 수동 ID 등록 없이 연재·완결 목록과 상세 정보를 수집하는 스크립트 |
| `scripts/update_platforms.py` | 네이버웹툰 재수집 없이 국내 플랫폼 목록·상태 갱신 |
| `scripts/sync_public.py` | 루트 화면 파일과 public 배포 파일 동기화 |
| `tests/services.test.cjs` | 브라우저 서비스 로직 및 AI 요청·실패 처리 회귀 테스트 |
| `tests/test_recommendations.py` | 서버 AI 호출·응답 검증·HTTP 오류 처리 테스트 |

일반 탐색에서는 장르끼리는 OR, 장르·분위기 태그·연재 상태·검색어 사이는 AND 조건을 적용합니다. AI 호출은 취향 창에서 추천을 제출할 때 발생하며, 페이지를 열거나 검색어를 입력할 때마다 호출하지 않습니다.

AI 추천에서는 자동 수집 목록과 선택한 국내 플랫폼의 공개 검색 결과를 합칩니다. 네이버웹툰은 최대 3개 질의, 나머지 선택 플랫폼은 주요 키워드 1개로 병렬 조회합니다. 키워드 검색을 공개하지 않는 서비스는 공개 작품 목록을 활용합니다. 검색 결과는 10분, 메타데이터는 24시간 캐시합니다.

서버는 플랫폼·장르·연재 상태를 강제한 뒤 키워드·분위기·관심등록 수로 후보를 좁힙니다. 각 플랫폼 후보를 번갈아 선택하고 동일 제목의 판본을 중복 제거합니다. 추천 개수는 1~18개, 기본 6개이며 후보 수는 기본 36개에서 요청 수에 따라 최대 72개로 늘어납니다. 선택한 개수를 네이버·카카오·기타에 고르게 나누며 기본 6개는 2·2·2입니다. 기타는 가능한 경우 서로 다른 플랫폼에서 선택합니다. 네이버웹툰과 시리즈는 네이버 그룹, 카카오페이지와 카카오웹툰은 카카오 그룹으로 합산합니다. 후보가 부족하면 사용자의 선택 조건 안에서 남는 자리를 다른 그룹에 배분합니다. AI가 정한 작품 ID·추천 이유·최종 배분을 서버가 검증하며, 배분을 어긴 응답은 오류로 처리합니다. 키와 인증 헤더는 프롬프트에 포함하지 않습니다.

추천 화면에는 수집 작품 수·검색으로 확인한 작품 수·AI 후보 수를 표시하고, 검색에서 발견한 작품에는 표시를 붙입니다. 검색 연결 실패 시 그 상태를 알리고 이미 수집한 정보로 추천을 계속할 수 있습니다. AI 자체 오류는 대체 결과로 위장하지 않습니다.

추천 대기 중에는 회전 표시·움직이는 대기 막대·경과 시간을 보여주고 입력과 중복 제출을 잠급니다. 실제 진행률이나 완료하지 않은 단계를 표시하지 않습니다. 취향 창을 닫으면 화면 하단의 진행 표시로 다시 열 수 있습니다. 성공·실패·타임아웃 모두 타이머와 대기 상태를 정리합니다.

AI 추천 결과에서 검색과 정렬은 현재 추천 목록에 적용합니다. 장르·분위기·연재 상태를 직접 바꾸거나 초기화하면 일반 탐색으로 돌아갑니다. API 인증·한도·네트워크·시간 초과 오류는 화면에 표시하며, 임의의 대체 결과를 AI 추천으로 표시하지 않습니다.

작품 정보는 각 플랫폼의 공개 검색 응답·작품 페이지에서 가져옵니다. 원본 주소는 `source`와 `url`, 검색 과정과 플랫폼별 조회 상태는 `retrieval.search`에 기록합니다. 공개 정보에 없는 작가·장르·연재 상태는 확인 필요로 표시하며, 완결 여부를 임의 추정하지 않습니다. 작품 ID는 플랫폼 접두어와 URL 해시를 사용해 충돌을 방지하고 기존 네이버 숫자 ID도 유지합니다.

서버는 최신 캐시를 `/api/generate?resource=catalog`로 제공합니다. 24시간이 지난 카탈로그는 요청이 들어오면 백그라운드에서 갱신하고 그동안 마지막 정상 데이터를 유지합니다. 네이버웹툰은 연재·완결 목록을 순회하며, 나머지는 공개 검색·대표 목록을 수집합니다. 범용 검색엔진 전체 검색이 아닌 각 공식 플랫폼 조회입니다.

비네이버 수집은 18개 장르·주제 검색어의 다음 페이지까지 읽습니다. 카카오페이지·카카오웹툰은 페이지당 최대 100개, 레진·봄툰은 30개씩 검색어당 최대 8페이지를 확인합니다. 카카오페이지·봄툰은 완결 전용 검색도 별도로 읽어 완결 상태를 확보합니다. HTML 기반 서비스는 공개 검색·요일·장르·완결 목록을 읽으며 제공 범위가 서로 다릅니다. 상세 메타데이터는 디스크에 24시간 캐시합니다. 범위를 넓힌 수집도 각 플랫폼 전체 작품의 완전 수집을 의미하지 않습니다.

지원 목록은 네이버웹툰·네이버 시리즈·카카오페이지·카카오웹툰·레진코믹스·리디·봄툰·탑툰·투믹스·미스터블루·북큐브·피너툰·원스토리·코미코·애니툰·무툰·포스타입·만화365·인터넷만화방입니다. 13개는 작품 정보 자동 조회, 원스토리·코미코·애니툰·포스타입·만화365·인터넷만화방은 공식 사이트 연결을 제공합니다. 국내 모든 서비스·모든 작품의 완전 수집을 의미하지 않습니다. 상세 범위는 [플랫폼 연결 문서](docs/PLATFORMS.md)를 참고하세요.

화면은 24개씩 표시하며 검색·플랫폼 필터는 전체 목록에 적용합니다. 일반 탐색의 추천순은 플랫폼을 번갈아 배치하며 플랫폼 내부 순서를 유지합니다. 관심등록순·가나다순과 AI가 정한 추천 순서는 유지합니다. 표지는 서비스별로 확인한 공식 이미지 호스트만 허용하고 알 수 없는 주소는 기본 표지로 대체합니다. 상세 제목을 이용해 배너·리뷰 링크가 작품명으로 표시되지 않도록 교정합니다.

보관함은 이 브라우저의 localStorage에 저장합니다. 로그인·기기 간 동기화는 제공하지 않습니다. 기존 저장 데이터와 섞이지 않도록 오늘의 덕질 전용 키를 사용합니다.

기존 식별자인 `StorageManager`, `ApiService`, `generateTripPlan`, `generateFallbackPlan` 등의 이름을 유지했습니다. 기존 `/api/generate`에 웹툰 요청을 추가했으며 여행용 함수의 이름과 기존 요청 방식도 보존합니다.

## 데이터 갱신과 배포 파일

1. `python scripts/update_catalog.py` — 연재·완결 목록에서 공식 작품 정보 자동 수집
2. `python scripts/sync_public.py` — 변경한 HTML/CSS/JS 및 데이터를 public에 복사
3. `node --test tests/services.test.cjs` — 서비스 로직 검증
4. `python -m unittest discover -s tests -p 'test_*.py' -v` — AI 서버 로직과 HTTP 요청 검증

작품을 추가하기 위해 ID를 직접 등록할 필요가 없습니다. 수집 후 `python scripts/sync_public.py`로 배포용 스냅샷을 맞춥니다. 갱신과 실시간 검색에는 인터넷 연결이 필요하며, 표지·줄거리의 권리는 원저작권자에게 있습니다. 공식 사이트의 내부 응답 형식이 바뀌면 수집 어댑터 수정이 필요할 수 있습니다.

Vercel의 기존 `public/`과 `/api/generate` 라우팅을 유지합니다. 원격 배포 시 호스팅 환경에도 `AI_API_KEY`, `AI_API_BASE_URL`, `AI_MODEL`을 등록해야 합니다. Windows 전역변수는 로컬 프로세스에 적용됩니다.
